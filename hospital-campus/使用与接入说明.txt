澄和医院 · 千人小镇医院院区

打开
双击“澄和医院.html”。无需安装依赖，无需启动服务器，可在断网状态使用。
HTML 内嵌 Three.js、OrbitControls、GLTFExporter、程序化模型、纹理、样式和交互。

操作
左键旋转；右键或 Shift + 左键平移；滚轮缩放。
触屏单指旋转，双指缩放和平移。空格暂停或继续，H 恢复总览。
提供院区总览、中心花园、门诊入口、急诊通道、屋顶设备和地下车库视角。
点击建筑可以单栋观察和导出。恢复全景会重新显示其他建筑。
三档画质、晨光/日间/夕照/夜间、动态速度、体积氛围、时间流转和巡游可在右侧设置。
最高档默认开启完整已实现细节。手机端初次打开默认收起设置面板。

院区与尺度
院区占地严格为 112 × 112 米，外围城市道路不计入。
Y-up，米制，地面中心原点，+Z 为主入口方向。
北侧住院中心 10 层，约 41 米；西南门诊中心 4 层，约 17 米；东南急诊中心 3 层，约 12.1 米；东侧独立医技中心 4 层，约 17.4 米。
包含方形中心花园、正交步行系统、7 米环形通道、急诊雨棚、地下车库实挖坡道、停车场、门卫室、后勤医废暂存站、导向牌、树木、灯、长椅和排水设施。
院区静态几何边界为 X/Z ±56 米，最高屋顶约 44.525 米，最低地下构造约 -4.475 米。

动态与细节
模型包含救护车停靠/驶离、环形交通车辆、车库进出车辆、28 名访客/医护/轮椅人物、自动门感应开合、道闸联动、植被风动与飞鸟。
暂停会冻结统一动画时间，镜头仍然可操作。
楼体包含窗框、窗台、板缝、层间构造、首层入口、雨棚、局部室内轮廓、屋顶设备、风机、通风管道、楼梯间与检修梯。
远景植被使用实例化叶簇；低画质切换为简化树冠，并减少可见人物和微细节。

城市接入
hospital-module.mjs 是模型工厂，不携带第二份 Three.js。
hospital-manifest.json 包含尺寸、建筑 ID、出入口、朝向和地下车库开挖范围。
town-integration.example.mjs 演示如何从宿主传入 THREE、scene、目标地块及地面处理适配器。

核心用法：
import { createHospital } from './hospital-module.mjs';
const hospital=createHospital({ THREE, embedded:true, quality:'high' });
hospital.root.position.set(目标地块中心X, 接地高度, 目标地块中心Z);
scene.add(hospital.root);
// 在小镇现有动画循环中调用，不再新增 RAF：
hospital.update(deltaSeconds,worldElapsedSeconds);

setQuality('high'|'medium'|'low') 调整细节。
setDynamicsEnabled(false) 暂停本模块。
setTimeOfDay(0～1 或 'morning'/'evening'/'night') 只修改医院发光材质，不修改小镇太阳。
dispose() 释放模块自己的几何、材质、纹理和实例，且可重复调用。

整个院区根节点不包含相机、灯光、天空、全局雾、渲染器、OrbitControls、背景地面或页面 UI。
没有修改千人小镇的现有街坊，未来选定目标街坊后再安装。

接入时重要的地面处理：
先移除目标 112 米地块原有建筑与景观，保留外侧城市道路。
车库是实际下沉模型，需要依据 manifest.excavations 在小镇原有地面、底板及地块下方铺路面上留洞。
局部开挖范围：X [-42,-28]、Z [-40,-20]、最低 Y -4.5 米，随整个医院一起平移/旋转。
若宿主地面仍为完整平面，车库会被遮挡；这是宿主地面需要开孔，不能通过抬高整个院区解决。
示例要求提供 prepareParcel，明确由小镇管理地块拆除和开孔，避免模型擅自修改宿主资源。

导出
hospital-campus.glb 为完整院区静态模型；hospital-emergency.glb 为急诊楼示例。
HTML 的“导出模型”不包含展示背景，保留医院当前静态几何和材质。
“导出城市接入模块”生成工厂代码和 manifest；它保留动态逻辑。
GLB 不烘焙网页实时交通和风动画。需要动态时使用 HTML 或模型工厂。

Blender
“澄和医院.blend”包含独立建筑父节点、医院模型集合、单独展示环境集合，以及总览/门诊/急诊/花园/屋顶/车库相机。
通过本地 127.0.0.1:9876 Blender MCP 实际执行了导入，并由 MCP 发起后台 Cycles 渲染；保留了原本 Blender 内的其他场景。
渲染图片保存在 outputs/blender-*.png。
最终工程附带 144 帧、24 fps 相机巡游关键帧；当前没有交付已经渲染完成的视频。

验证与制作记录
第一轮：outputs/01-graybox.png 检查体量和方形布局。
第二轮：outputs/02-*.png 检查入口、花园、屋顶和车库，修正了坡道法线、展示地面挡住车库、近景标题遮挡和行人穿越门诊楼的问题。
第三轮：细化叶簇、建筑板缝、机组格栅、检修梯和车辆接地；自动门与道闸改为与附近人员/车辆联动；抬高车库标识，避免挡住汽车。
第四轮：outputs/verification.json 保存断网、边界、四栋独立建筑、拖拽/平移/缩放/投影、暂停、巡游中断、昼夜、GLB 导出、模块加载/卸载、手机布局等检查结果。
以半秒间隔采样了两分钟动态路线，检查人物与车辆未穿入四类主楼，且没有超出院区边界。
浏览器检查使用本机 Microsoft Edge 无头模式；物理手机与其他硬件性能未实测。

实际限制
这是可继续精修的程序化微缩模型，人物、车辆、部分室内和设备采用简化几何，不能视为照片级资产或医疗建筑工程图。
车辆按展示路径运行，没有完整交通优先权、精细碰撞避让或人体足部 IK。
HTML 中玻璃为 PBR 环境反射近似，没有逐窗实时光线追踪。
云层使用三维密度采样；近地氛围为简化体积介质与距离雾，未实现完整的场景深度参与介质积分。
主要建筑都已独立分组，但没有为每一个室内空间建立完整结构。
Blender 保存网页所导出时刻的几何快照，未烘焙全部网页动画。两种渲染器的照明与材质观感存在差异。
