# 千人小镇 · 城市构筑工作台

这是一个可以本地运行、逐栋替换建筑的 Three.js 城市原型。16 个 112 × 112 米街坊、56 栋住宅、4 栋医院建筑、1 栋超高层地标、完整道路与中央 64 米预留走廊组成场景。住宅采用统一模块原型，后续可独立精修。

## 运行

电脑安装 Node.js 后，在本目录运行：

```powershell
npm start
```

打开 http://127.0.0.1:5173 。运行时 Three.js 和所有用到的模块均从本地加载，不依赖 CDN。已有 vendor 文件时不需要 npm install。

也可以双击 `启动小镇.cmd`，再按终端提示访问网址。

## 使用

- 鼠标左键旋转，右键或 Shift + 左键平移，滚轮缩放；触屏使用单指旋转、双指缩放和平移。
- 单击建筑查看信息，双击进入单栋观察。全景按钮或 H 键恢复全部建筑。
- 支持透视和正交视角、晨光/日间/黄昏/夜景、三档画质、自动巡游、时间流逝、动态速度、暂停，以及车辆与自然动态开关。
- 空格暂停或继续城市动态。镜头仍可操作。
- 顶部“自由视角”进入飞行相机：拖动转向，WASD 移动，Q/E 下降与上升，Shift 加速，滚轮或滑杆调速；Esc 返回进入前的镜头，F 可切换。手机提供双摇杆、升降按钮和双指推进。
- 电影模式启用环境遮蔽和 4096 像素阴影。流畅模式降低像素比与阴影采样，关闭后期。
- 手机端默认收起设置面板，点击加号展开。

## 逐栋制作

住宅编号沿用 QR-001 至 QR-064，其中 QR-049 至 QR-052 已被医院的四栋独立建筑替换，QR-005 至 QR-008 所在街坊已替换为云际中心。每栋建筑是独立 Group，单位为米。

1. 点击建筑，再点“导出 GLB”，得到这栋建筑的独立模型。
2. 在 Blender 中导入 GLB 并修改，保持底部中心原点和合理尺寸，再导出 GLB。
3. 回到网站选中建筑，点“替换 GLB”，加载新模型。网页按原建筑高度等比匹配，保持新模型自身比例。
4. “恢复原型”可以撤销该栋替换。替换暂存于当前浏览会话，刷新会恢复原型。
5. 顶部“导出场景”保存城市 GLB 静态快照，包含当前替换。实时交通、风和巡游不烘焙进 GLB。

GLB 支持标准未压缩模型与内嵌纹理；没有配置 Draco/KTX2 解码器。建议单栋不超过 50 MB。

如要永久替换源码原型，可在 `dist/city.js` 的 `makeBuilding` 中接入对应建筑 ID 的模型加载。保留建筑 Group 的 ID、位置和元数据，避免更改整座城市坐标。

## 布局与动态

`dist/city.js` 中的 PLAN、buildCity、makeBuilding、createLife 管理布局、建筑与交通。当前为确定性种子 1101。

- 街坊边长 112 m，常规道路宽 28 m，中央沿线道路宽 24 m。
- 中央空地严格保留 x ∈ [-32,32]、z ∈ [-300,300]。未来河流应在独立 Group 中生成，不直接改写两侧建筑。
- 当前没有河面、河岸、桥梁。可勾选“河道预留边界”查看位置。
- 改变布局时，需要同步调整地块、道路、交通路径和相机范围，不能只修改一个数字。
- `createLife` 保留 48 辆城市动态车和 98 名住宅街坊行人。医院独立管理院内车辆与行人，并跟随全局动态开关。
- 交通是程序化展示：车辆沿圆角街坊路径行驶，并在设定转弯区等待相位；行人目前沿各街坊人行道循环。不是完整的路口优先权或行人过街仿真。
- 树木采用实例化顶点风动画；天空云层使用 12 步三维密度采样；近地氛围采用距离雾。飞鸟使用简化几何动画。
- 建筑/设施重复件使用 InstancedMesh；纹理启用 mipmap 和视锥裁剪。当前没有实现完整距离 LOD 或设备自动降档，三档画质可手动切换。

## Blender MCP

本次已通过项目专用 stdio MCP 桥接实际调用本地 Blender 5.2.2，使用 Cycles/OPTIX 渲染。没有修改用户全局 MCP 配置，也不需要在正在打开的 Blender 中安装插件。

安装项目隔离的 Python 依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r tools/requirements.txt
```

桥接提供三个工具：`blender_inspect_environment`、`blender_start_city_render` 和 `blender_get_render_status`。

```powershell
.\.venv\Scripts\python.exe tools/call_blender_mcp.py blender_inspect_environment
.\.venv\Scripts\python.exe tools/call_blender_mcp.py blender_start_city_render '{"samples":64}'
```

客户端会保持 MCP 会话，直到 Blender 后台任务结束；在 Windows 上不要提前关闭任务终端。渲染日志、工程和图片保存在 `outputs/render-<jobid>/`，最新任务写入 `outputs/active-render.json`。

默认 Blender 路径为 `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`；其他电脑可用环境变量 `CITY_BLENDER_EXE` 指定。

`outputs/qianren-city.json` 是网页导出的程序化基准场景。通过 `window.cityApp.exportCity()` 获取，`tools/inspect_scene.py` 可自动生成。JSON 不包含浏览器内临时替换的 GLB；修改后的完整视觉场景请直接使用网站顶部 GLB 导出。

`tools/blender_scene.py` 在 Blender 中按同一数据重建建筑和设施、设置 PBR 材质/程序化表面/晨光/轻体积雾，保留独立建筑原点与编号，保存工程并输出两张渲染图。它重建的是基准场景的静态模型，网页实时交通、招牌 canvas 纹理和风动画不自动转换。GLB 导出则可保留当前静态可见几何与招牌纹理。

工程内另有 144 帧、24 fps 的相机巡游关键帧，可继续制作并在 Blender 渲染视频。

```powershell
npm run check
python tools/verify_web.py
```

网页验证需要 Python Playwright 与本机 Microsoft Edge。`outputs/verification.json` 保存实际检查结果，截图位于 outputs。

代码分工：`dist/index.html` 为界面，`dist/style.css` 为布局，`dist/main.js` 为渲染/相机/交互/时段，`dist/city.js` 为建模/材质/交通。`tools/vendor.mjs` 从已安装的 Three.js 收集运行依赖。Three.js 版本和许可保存在 package-lock.json 与 dist/vendor/THREE-LICENSE.txt。

当前定位为可扩展的街区基础工程。建筑为程序化原型，树木、人物与车辆采用简化几何；单栋照片级建筑精修可通过 GLB 替换逐步完成。

## 自由视角

顶部新增第四个“自由视角”模式，保留进入时的相机位置和方向，以透视飞行相机观察城市。画面可朝上查看立面、向下观察屋顶，近裁剪缩短至 0.15 米，便于查看建筑细节。

电脑：按住鼠标拖动转向；W/S 前后移动，A/D 左右移动，Q/E 下降与上升，Shift 三倍加速。方向键和 PageUp/PageDown 也可移动。滚轮与底部滑杆调节移动速度（1—120 米/秒），左侧加减按钮可沿视线推进或后退。

手机：左摇杆移动，右摇杆转向；中间按钮升降，画面可拖动转向或双指推进。控制区与设置面板分开，进入时自动收起设置。

退出按钮、Esc 或再次点击自由视角返回进入前的位置、投影与建筑可见状态。从正交模式进入时会暂用透视相机，退出后恢复正交。总览、街区漫游、建筑观察、医院/地标定位和巡游可直接离开自由模式。城市动态暂停时相机仍能移动，且移动速度独立于城市动画倍速。

窗口失去焦点、触摸被取消或打开帮助时会清除持续输入，防止镜头自行漂移。相机最低高度为 0.8 米，采用无碰撞飞行观察。

`dist/free-view.js` 管理飞行输入与姿态，复用城市帧循环；`dist/main.js` 管理模式切换、相机和界面恢复。未创建额外渲染器或动画循环。`python tools/verify_free_view.py` 实测 39 项键鼠、移动端和模式恢复行为，结果与截图位于 `outputs/free-view/`。

## 交互帧率优化

修复拖动视角时每帧重复绘制全城的性能问题。原水面通道在相机移动时绕过刷新限制，每帧同时执行反射和折射；霁衡中心少量玻璃的屏幕透射又使这些通道额外绘制全城背景。叠加每帧阴影和大量点光源后，实测拖动约10FPS。

新增 dist/render-budget.js：

- 水面按时间预算刷新，拖动时将反射、折射分到不同帧；保留各自的投影矩阵，水面不可见时跳过通道。
- 默认画质在真实灯具中按观察位置调度8个点光源，流畅4个、电影12个。61个源灯具及其昼夜/模块开关继续保留；灯光池不写入城市模型。
- 平面玻璃在普通画质及镜头移动时使用原PBR反射与透明度，静止电影模式恢复屏幕透射。每帧结束恢复源材质，GLB与JSON仍保留原始透射参数。
- 将影子刷新与水面更新错开，并按画质限制频率；天空环境探针在镜头运动后更新。
- 运动时自适应降低绘制分辨率、暂缓光晕与环境遮蔽，停稳后恢复清晰度及对应画质后期。
- 世界矩阵每帧统一更新，供主画面和离屏通道复用；小于像素的普通网格暂时不绘制，下一帧重新评估。源模型、显隐状态、编辑、选择和导出在帧结束后恢复。

本机Edge / RTX5060 Laptop、1280×800、初始DPR1、精致画质、相同6秒镜头路径对比，使用真实GPU渲染，无渲染替身：

| 路径 | 拖动FPS | 95%帧耗时 | 每帧平均绘制调用 |
| --- | ---: | ---: | ---: |
| 旧渲染路径 | 9.98 | 109ms | 27,424 |
| 优化后 | 64.07 | 30.3ms | 3,136 |
| 优化后重复测量 | 64.69 | 30.3ms | 3,129 |

该测试中拖动采样为0.75倍，停稳恢复1倍；完整源模型和导出不降采样。其他设备的实际帧率取决于GPU、浏览器和分辨率。结果位于 outputs/performance/benchmark.json，昼夜截图位于同目录。

验证：启动本地服务器后运行 tools/verify_render_budget.py（调度、源材质、光源、矩阵与导出契约）；tools/benchmark_performance.py（同场景真实GPU对比）；既有建筑接入、替换及导出检查继续适用。灯光预算使用相机图层隔离源灯具，保持GLB中的原始灯具；帧内显隐和材质修改都通过 finally 恢复。
